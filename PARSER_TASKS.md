# Paine Parser — практические задания по Kotlin

Небольшие практические задания для начинающего Kotlin-разработчика на основе проекта **paine-parser**.

**Репозиторий:** https://github.com/paineofficial/paine-parser

**Цель:** научиться вносить небольшие изменения в существующее Spring Boot приложение, работать с Kotlin, Jsoup и REST API, а также использовать Git и Pull Request.

> **Важно:** задания рассчитаны на новичка. Не нужно добавлять новые библиотеки, переписывать архитектуру приложения, подключать базу данных или использовать Playwright. Достаточно существующего Spring Boot приложения и Jsoup.

## Как выполнять задания

1. Создай **отдельную ветку от `develop`** для выбранного задания. Имя ветки указано под заголовком задачи.
2. Реализуй функционал, преимущественно используя существующий `WebsiteParserService`.
3. Добавь отдельный GET endpoint в `PageReportResourceV1` для вызова нового метода.
4. Проверяй результат через браузер, Postman или `curl`.
5. Сделай коммит, отправь ветку в GitHub и открой Pull Request **в `develop`**.
6. Переходи к следующему заданию после проверки предыдущего.

**Важно для проверки:** примеры JSON ниже показывают *формат ответа*, а не гарантированные данные с сайта. Выбирай страницы, где нужные элементы точно есть. Если на сайте нужного элемента нет — верни результат, указанный в критериях задачи.

### Общий чек-лист готовности (для каждой задачи)

- [ ] Создана отдельная ветка от `develop`.
- [ ] Добавлен метод в `WebsiteParserService`.
- [ ] Добавлен GET endpoint в `PageReportResourceV1`.
- [ ] Ответ возвращается в JSON (при необходимости создан `data class`).
- [ ] Функционал проверен на подходящей HTML-странице.
- [ ] Приложение успешно запускается, ошибок компиляции нет.
- [ ] Изменения закоммичены и создан Pull Request в `develop`.

## Задание 1. Получить заголовок страницы

**Ветка:** `feature/01-page-title`  
**Сложность:** ⭐ Очень легко

**Что сделать:** создать endpoint, который принимает URL и возвращает содержимое HTML-тега `<title>`.

**Пример запроса:**

```http
GET /api/v1/page-report/title?url=https://example.com
```

**Пример ответа:**

```json
{
  "title": "Example Domain"
}
```

**Чек-лист приёмки:**

- [ ] URL передаётся через параметр `url`.
- [ ] Возвращается текст из тега `<title>`.
- [ ] Если тега `<title>` нет — возвращается пустая строка `""`.

**Что потренируешь:** функции, `String`, Jsoup, HTML-теги.

## Задание 2. Получить контакты со страницы

**Ветка:** `feature/02-page-contacts`  
**Сложность:** ⭐⭐ Легко

**Что сделать:** создать endpoint, который принимает URL и ищет на странице **первую электронную почту** и **первый номер телефона**.

Для начала достаточно брать контакты только из ссылок `mailto:` и `tel:`. Искать контакты в обычном тексте не нужно.

**Пример запроса:**

```http
GET /api/v1/page-report/contacts?url=https://example.com/contacts
```

**Пример ответа:**

```json
{
  "email": "info@example.com",
  "phone": "+375291234567"
}
```

**Если контактов нет:**

```json
{
  "email": null,
  "phone": null
}
```

**Чек-лист приёмки:**

- [ ] URL передаётся через параметр `url`.
- [ ] Почта берётся из ссылки `mailto:` без префикса `mailto:`.
- [ ] Телефон берётся из ссылки `tel:` без префикса `tel:`.
- [ ] Если контактов несколько — возвращается первый каждого типа.
- [ ] Если почты или телефона нет — соответствующее поле равно `null`.

**Что потренируешь:** `String?`, nullable-типы, `selectFirst()`, `data class`.

## Задание 3. Получить все ссылки со страницы

**Ветка:** `feature/03-page-links`  
**Сложность:** ⭐⭐ Легко

```http

```

**Пример ответа:**

```json
{

    "https://example.com/contacts"
```

- [ ] Пустые адреса не попадают в результат.
- [ ] Если ссылок нет — возвращается пустой список `[]`.

**Что потренируешь:** `List`, `map`, `filter`, `absUrl()`.

## Задание 10. Найти слово на странице

**Ветка:** `feature/10-keyword-search`  
**Сложность:** ⭐⭐ Легко

**Что сделать:** создать endpoint с двумя параметрами: `url` и `keyword`. Он должен определять, есть ли указанное слово или подстрока в **видимом текстовом содержимом HTML-страницы**.

**Пример запроса:**

```http
GET /api/v1/page-report/search?url=https://example.com&keyword=example
```

**Пример ответа:**

```json
{
  "keyword": "example",
  "found": true
}
```

**Чек-лист приёмки:**

- [ ] Endpoint принимает параметры `url` и `keyword`.
- [ ] Поиск производится по тексту страницы, а не по исходному HTML-коду.
- [ ] Поиск не зависит от регистра (`Example` = `example`).
- [ ] Если текст найден — возвращается `true`, иначе `false`.
- [ ] Совпадение подстроки считается успешным (не нужно искать только целые слова).

**Что потренируешь:** `Boolean`, `contains(ignoreCase = true)`, несколько `@RequestParam`.

## Как сдавать работу

В описании Pull Request укажи:

```markdown
## Что сделано
- 

## Как проверить
- Запрос: `GET /api/v1/page-report/...`
- Ожидаемый ответ: ...

## Чек-лист
- [ ] Создал ветку от develop
- [ ] Реализовал функционал
- [ ] Проверил работу через HTTP-запрос
- [ ] Приложение запускается
```

**Главное правило:** одна маленькая задача — одна ветка — один Pull Request. Старайся делать решение простым и понятным. Не нужно пытаться сразу построить универсальный парсер всех сайтов.

> Для учебных проверок используй общедоступные страницы, на которых разрешены такие запросы, или подготовленные локальные HTML-файлы. Не делай массовых запросов к чужим сайтам.

Удачи в изучении Kotlin! 🚀
